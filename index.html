The challenge

Every week, progress had to be collected from site engineers, checked, keyed into P6 and fixed after import errors. That took at least 3 days, so management saw status late and in mixed formats.

My measurement

Update time fell from at least 3 days to about 20 minutes per cycle.

Verified from project files

  • 16 weekly cycles completed, 30 Jul to 12 Nov 2026.
  • Full output set on every cycle: validation, import files, dashboard, site layout, look-ahead, group PDFs.
  • 46 Python scripts (about 19,600 lines) with 150 automated tests.
  • The dashboard reconciles with the server calculation on 17 reference figures each build.

A Time Impact Analysis variant of the same claim gives 190 working days (266 calendar days). The prolongation cost entitlement is reserved.

  1. Start from the consultant-approved baseline XER for the hall.
  2. Insert each delay event as its own fragnet: stop order, suspension period, resumption order, deep foundation works.
  3. Produce an impacted P6 schedule per event and measure the shift of the completion date on the longest path.
  4. Convert working days to calendar days on the project calendar and tie each event to its contract clause.
  5. Write the claim narrative and present it as a forensic submission deck, built with AI tools.

Central 32 Schools 4D Portfolio

An offline 4D portfolio that plays back planned vs actual progress for 32 schools and opens a 3D model of each one.

Rendered in the 4D viewer · school at completion
MR1-M11 at its forecast finish, Feb 2028.
  1. The P6 XER (32 projects, one data date) is read in the browser.
  2. Activities map to buildings, floors and disciplines by P6 activity codes, which cover 100% of activities.
  3. A working-time calendar engine computes planned progress, weighted by P6 cost loading.
  4. The portfolio view shows playback, delays and school cards; each school opens a three.js 3D viewer.
  5. Each release ships an internal master and a read-only external viewer with a SHA-256 manifest.

Gantt charts don't show where on site the work stands. The 4D view shows, per school and per building, what should be built by a date and what actually is.

Schematic at building and floor level. Element-level 4D needs an IFC export from Revit, the next step. The concept builds on a 16-school version a planning colleague made for another region.

  • 4 numbered releases between 15 Oct and 8 Nov 2026.
  • 4,516 overdue activities flagged with total float in the portfolio view.
  • Planned and actual 4D, playback by day or week, discipline filters, P6 forecast after the data date, day and night scenes.

The challenge

Daily manpower and equipment figures came in late and in different formats. Site issues were lost in chat threads, with no owner or deadline.

  • Daily site reports: manpower by trade, equipment and status.
  • Issue register: assign to a specialist, track the timeline, analyse and export to PDF.

How I work

The rules behind every tool above.

P6 stays the source of truth

Tools read exports and write import files. Nothing edits the live schedule behind the planner's back.

Validate before import

Every cycle is checked school by school before a single date reaches P6.

Reconcile to the riyal

A new calculation must reproduce P6's own numbers before anyone sees its answer.

Label honestly

Schematic is called schematic, and a measured result is kept apart from an estimate.
